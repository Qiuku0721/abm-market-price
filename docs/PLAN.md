## 1. 目标

自动采集《暗区突围》游戏内市场（子弹类物品）的价格：

1. **手机端 Kotlin App（全自动）**：周期性截屏 → 本地识别（OCR）市场界面中的「子弹名称 + 价格」→ 模拟点击完成列表滚动/翻页遍历 → 将记录经局域网上报给电脑端。
2. **电脑端 Python 程序（记录与统计）**：接收上报 → 存入 SQLite → 提供本地浏览器统计页面（最新价、走势、历史明细）→ 支持导出 CSV / Excel。
3. 全程无需人工操作，价格记录周期化、可追溯、带截图快照，供核对识别是否正确。

---

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 架构分工 | **App 全自动**：识别与模拟点击全部在手机端完成；电脑端只做记录与统计 |
| 电脑端技术栈 | **Python**（FastAPI + SQLite + 本地 Web 页面） |
| 运行载体 | **安卓真机**（与电脑同一局域网） |
| 画面回传形态 | App 上报**识别快照/关键帧缩略图**，电脑端留存供抽查审计；不做实时视频推流 |

## 3. 默认假设（可在实现中调整）

- 游戏 UI 为自绘渲染（Unity 等），Android 无障碍服务**大概率读不到控件树**。因此识别采用
  **MediaProjection 截屏 + Google ML Kit 文本识别**；点击采用**无障碍 `dispatchGesture` 坐标点击**。
- 查找「对应名称」**默认走市场列表滚动遍历 + OCR 匹配**，避免向游戏内输入框注入文本；
  「搜索框输入」作为备选链路（无障碍 setText → 剪贴板粘贴 → 自定义 IME，三级降级），不进入首版主流程。
- 子弹名称是**精确全名匹配**（OCR 结果经归一化后与清单比对）。
- 电脑端与手机端同处一个局域网，App 内配置电脑端 IP:端口。
- 电脑端 Python 版本要求 **3.10+**。

## 6. 手机端 App 采集流程（核心编排）

一次「全量采集周期」的状态机：

```
IDLE
 └─▶ START（校验：悬浮窗/无障碍/录屏权限、PC 可达性）
      └─▶ GOTO_MARKET       切换到游戏市场页（若有锚点模板则校正坐标）
           └─▶ SCAN_LIST    截屏 → OCR → 与清单比对
                ├─ 命中：读取价格 → 去重校验 → 入上报队列 → 标记清单项完成
                ├─ 未命中 → SCROLL（向下滚动一屏）→ 继续 SCAN_LIST
                └─ 到底 / 超时 → 复位（回市场顶部或退出重进）
                     └─▶ 全部清单项完成 / 达到周期上限 → REPORT → IDLE（等待下一周期）
```

关键机制：
- **锚点校正**：以固定 UI 元素（如「市场」Tab / 搜索框图标）的小模板做模板匹配，校正由于分辨率/布局偏移带来的点击坐标漂移。
- **失败重试**：OCR 空结果或价格异常（超出合理区间）最多重试 N 次后放弃该项并记录原因。
- **超时复位**：单步骤超时（如滚动无变化）自动回退到市场页重新开始，避免卡死。
- **防呆限频**：相邻点击间隔带随机抖动；默认每轮全量采集间隔可配置（默认 5 分钟）。

## 7. 数据与协议（详见 docs/PROTOCOL.md）

- 上报方式：手机端 `POST http://<PC_IP>:8600/records`，批量 JSON。
- 记录字段：`device_id / bullet_name / price / currency / market_type / captured_at / snapshot(可选 base64 缩略图)`。
- 快照：另存为文件，`POST /snapshots`（multipart）或在记录中带引用 id。
- 电脑端去重键：`(device_id, bullet_name, price, captured_at 取整到分钟)`。

## 8. 电脑端功能清单

1. `POST /records`：批量接收并入库（含 schema 校验、价格校验、去重）。
2. `POST /snapshots`：接收快照图片，落盘 `static/snapshots/<date>/`。
3. `GET /api/*`：
   - `/api/records?bullet=&from=&to=` 明细查询；
   - `/api/latest` 各子弹最新价；
   - `/api/trend?bullet=&window=` 走势点；
   - `/api/bullets` 清单 CRUD（含监控启停）。
4. 导出：`GET /export/csv`、`GET /export/excel`（按子弹/时间段）。
5. 本地 Web 页面：子弹价格卡片、折线走势、明细表、清单管理、最近快照抽查（人肉核对 OCR 是否正确）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 游戏反作弊检测自动操作 → 账号封禁 | 高 | 限频（默认 5 分钟/轮）+ 点击间隔随机抖动 + 「人工放行」开关（每轮开始前在 App 上确认）＋ 可随时停止；文档中显著提示合规与封号风险 |
| 无障碍/自绘 UI 读不到控件树 | 高 | 识别走截图 OCR + 坐标点击（已默认） |
| OCR 对游戏美术字识别率低 | 中 | 价格区域模板裁剪后识别；数字白名单；结果区间校验；快照留档供人工抽查调参 |
| 搜索框文字输入困难 | 中 | 首版走「列表遍历」；输入方案作为备选链路 |
| Android 后台限制杀进程 | 中 | 前台服务 + 通知；屏幕常亮策略可配置 |
| 断网/PC 离线 | 低 | App 本地队列缓存，恢复后重传 |
| 本机缺 Python/Android SDK | 低 | docs/SETUP.md 提供安装步骤；代码先静态自检，运行验证留待环境就绪（见 §10） |

## 10. 已知限制与验证边界

- **本开发机（Windows）未安装 Python 与 Android SDK**：Phase 2/3 产出的代码可静态审阅，但「运行级验证」（编译、pytest、uvicorn 冒烟）需在安装 docs/SETUP.md 所述环境后执行；文档中给出每条验证命令及预期输出。
- 端到端真机回归（价格与游戏内实价一致性）需真实游戏账号，列出回归清单由用户执行。
- 本工具仅限学习与研究用途；使用者需自行承担账号风险。
